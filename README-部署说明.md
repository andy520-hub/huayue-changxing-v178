# README-部署说明

# 华越畅行 · PWA 手机部署包（V1.7.5）

把「华越畅行」部署为手机上的"类原生 App"：HTTPS 托管 → 手机浏览器打开 → 添加到主屏幕 → 全屏启动、有图标、离线也能打开界面。

## 一、这个包里有什么

| 文件 | 作用 |
| --- | --- |
| `index.html` | 主程序（原 huayue.html + PWA 头信息 + Service Worker 注册） |
| `manifest.webmanifest` | PWA 清单：名称、图标、全屏模式、主题色 |
| `sw.js` | Service Worker：缓存应用外壳，主屏图标离线可开界面（机翻仍走网络） |
| `icon-192.png` / `icon-512.png` | 安卓/通用图标 |
| `icon-maskable-512.png` | 安卓自适应（遮罩）图标 |
| `apple-touch-icon.png` | iOS 主屏图标（180×180） |
| `icon.svg` | 图标源文件，便于二次修改 |
| `gen_icons.py` | 图标生成脚本（需 cairosvg） |
| `netlify/functions/translate.js` | 可选·百度翻译服务端代理（隐藏密钥，详见第六节） |
| `netlify/functions/asr.js` | 可选·百度语音识别（ASR）服务端代理（隐藏密钥，详见第九节） |
| `netlify/functions/whisper.js` | 可选·OpenAI Whisper 云端识别代理（中/越/泰/英高精度，详见第十一节） |

> 部署时**整个文件夹一起上传**，不能只传 index.html，否则图标/离线会缺。

## 二、托管（三选一，都自带 HTTPS）

### 方式 A：Netlify Drop（最快，拖拽即上线）

1. 电脑浏览器打开 [https://app.netlify.com/drop](https://app.netlify.com/drop)
2. 把 `huayue-pwa` 整个文件夹拖进去
3. 几秒后得到一个 `https://xxxx.netlify.app` 地址，直接给手机用

> 海外节点，国内访问可能偏慢；长期用建议方式 B/C。

### 方式 B：国内对象存储静态托管（国内访问快，推荐长期用）

- 腾讯云 COS / 阿里云 OSS / 七牛云 / 又拍云 的「静态网站托管」
- 上传整个文件夹 → 开启静态网站 → 用默认域名（自带 HTTPS，无需备案即可访问）
- 把 `index.html` 设为默认首页

### 方式 C：公司自己的 HTTPS 服务器

- 把整个文件夹拷到站点目录（Nginx/IIS/Apache），确保走 **https**
- 给 `.webmanifest` 配 MIME：`application/manifest+json`（部分服务器默认当下载，需补这一条）

## 三、手机"添加到主屏幕"

### 安卓（Chrome / Edge）

1. 用 Chrome 打开你的 https 地址
2. 右上角「⋮」→ 选 **「安装应用」**（或「添加到主屏幕」）
3. 桌面出现「华越畅行」图标，点开全屏运行，无地址栏

### iOS（Safari，必须用 Safari）

1. 用 **Safari** 打开 https 地址（微信内置浏览器不行）
2. 底部「分享」按钮 → 下滑选 **「添加到主屏幕」**
3. 桌面出现图标，点开全屏运行

## 五、以后怎么更新

1. 替换 `index.html`（新版本）
2. **同时**把 `sw.js` 的 `const CACHE = 'huayue-v1.7.5';` 改成更新后的版本号（本包已改好）——否则老用户拿到的是缓存旧版
3. 重新上传覆盖；用户端重开一次 App 即更新

## 六、让「互译」在国内也稳：接百度翻译（推荐，可选）

默认「互译」走公共接口 MyMemory，国内常被墙/超时。本包已内置**百度翻译**作为优先引擎，失败自动回退 MyMemory，并缓存已翻译结果（重复句离线也能秒回）。

> 申请免费密钥：https://fanyi-api.baidu.com → 注册 → 创建「通用翻译」应用 → 拿到 **APPID** 和 **密钥**。
> 免费额度 200 万字符/月，国内直连，速度稳定。

### 方式 A：前端直连（最简单，零后端）

打开 `index.html`，找到这段（在翻译配置区），填上你的 APPID / 密钥：

```js
const BAIDU_APPID = '你的APPID';
const BAIDU_KEY   = '你的密钥';
```

保存、重新上传即可。优点：不用服务器；缺点：密钥会出现在前端代码里（低预算个人工具通常可接受，百度也支持「只允许某些 IP」白名单兜底）。

### 方式 B：服务端代理（密钥安全，推荐对外发布时用）

把密钥放服务器端，前端只填代理地址，密钥不出浏览器：

1. 部署 `netlify/functions/translate.js`（见文件内注释；Vercel 用 `api/translate.js` 等价）；
2. 在托管后台设环境变量 `BAIDU_APPID` / `BAIDU_KEY`；
3. 前端 `index.html` 里把 `BAIDU_PROXY_URL` 填为代理路径，例如：
   ```js
   const BAIDU_PROXY_URL = '/.netlify/functions/translate';
   ```

### 回退与缓存

- 百度不可用（密钥未配/网络异常）时，**自动回退 MyMemory**，界面照常能用；
- 已翻译过的句子会写入浏览器 `localStorage`，**断网也能秒回历史译文**（仅对重复内容有效，新句子仍需联网）。

## 七、重要提示（正常现象，非故障）

1. **语音输入**：网页麦克风只在 **https** 下可用。挂到本包方式的 HTTPS 站点即可解锁；若仍不可用，用手机输入法的语音键说话转文字（主推用法）。详见第八节。
2. **机翻联网**：互译需联网（百度或 MyMemory）。公司 WiFi 若拦出站，手机切蜂窝数据；界面与场景句/词库/朗读是本地数据，不受影响。
3. **朗读**：iOS 自带越南语语音；安卓 Chrome 多数自带，个别机型需在系统「文字转语音」里装越南语语音包。
4. **Service Worker 需安全源**：只在 https（或 localhost）下注册生效；纯 http 局域网部署时 SW 不启用，但 App 本体照常能用（只是没有离线缓存）。

## 八、语音输入（本版已优化）

点「语音输入」后，按钮会立刻变红并显示「正在启动麦克风…」，进入聆听后显示「请说中文…点击停止」；再点一次即停止。主互译页底部会出现**麦克风电平条**，说话时绿条应随音量跳动。

**电平条怎么读（一眼定位问题）**

| 现象 | 含义 | 处理 |
| --- | --- | --- |
| 绿条随说话跳动 | 麦克风正常、确实收到声音 | 若仍没出字，是**识别服务器**问题（国内 Chrome 常被墙），改用输入法语音键 |
| 绿条几乎不动 | 麦克风没收到声音 | 检查是否静音、麦克风被占用、或设备选错 |
| 点击后提示「本地文件(file://)」「不是 https」 | 浏览器在非安全环境禁用麦克风 | 必须用 **https 网址**打开，别直接双击 html |
| 提示「权限被拒绝」 | 浏览器拦了麦克风 | 点地址栏锁图标 → 允许麦克风 → 重试 |

### V1.4.4 / V1.4.3 修了什么（重要）

- V1.4.4：删除含真实姓名的示例句，全站不再出现任何真实姓名。

上一版语音输入能启动、能听到声音，但**出字是 **`undefined undefined`：浏览器识别结果的取值写错了字段（`results[i].transcript` 应为 `results[i][0].transcript`），每个字都取成 `undefined`。本版已修正，并加了双重兜底：

- 兼容两种结果结构（标准 `results[i][0].transcript` 与部分实现的 `results[i].transcript`）；
- 写入前过滤 `undefined` / `null` 字样，**永远不会再把 undefined 打进输入框**；
- 如果麦克风正常工作但一个字都没拿到（国内 Chrome 的语音服务器连不上），停止时会明确提示，而不是静默无反应。

> 若更新后还是「说完没出字」，说明是**识别服务器不通**（不是本程序的 bug）：请按第九节配百度语音识别，或直接用手机输入法的语音键。

**为什么国内 Chrome 常识别不了**：内置语音识别依赖浏览器厂商的语音服务器（Chrome 走 Google，国内不通）。因此：

- **最稳的路子是用输入法语音键**：中文输入法点麦克风说中文；越南同事用 Gboard/越南语键盘说越南语，转成文字再点翻译，100% 可用。
- Edge、iOS Safari、海外网络下的 Chrome，内置按钮一般可正常用。
- 对话模式（整屏递给对方看）为不挡内容，只保留红色脉冲按钮提示，不显示电平条浮层。

## 九、让国内 Chrome 也能「直接说中文出字」：接百度语音识别（ASR，可选）

内置语音识别在国内 Chrome 上常被墙（连不上 Google 语音服务器）。本包额外接入了**百度语音识别**：配置后，国内 Chrome / 安卓点「语音输入」即可直接说中文出字，不再依赖被墙的浏览器引擎。

> 注意：百度「语音识别」与第六节「翻译」是**两套独立产品、密钥不同**，需分别申请。百度 ASR **只支持中文普通话**，不支持越南语/泰语；越南语、泰语想高精度识别请改用第十一节的 OpenAI Whisper 云端方案（V1.5.1 新增，V1.6.0 起支持四语种，可选）。

**为什么必须走服务端代理**：① 浏览器无法跨域直连百度接口；② Secret Key 绝不能放前端（会被扒去无限刷额度）。包里已附 `netlify/functions/asr.js` 代理。

**配置（三步）**

1. 申请密钥：到 [https://console.bce.baidu.com/ai](https://console.bce.baidu.com/ai) → 语音技术 → 创建应用，拿到 **API Key / Secret Key**（有免费额度，现场够用）。
2. 部署代理（二选一）：
   - **Netlify**（推荐）：用 `netlify-cli` 部署（拖拽上传不支持函数）：在项目根目录执行 `netlify deploy --prod --dir .`；或在后台「Connect to Git」连上含本文件夹的仓库。然后在 Build & Deploy → Environment variables 设 `BAIDU_ASR_APIKEY` / `BAIDU_ASR_SECRET`。
   - **Vercel / 自建 Node**：把 `netlify/functions/asr.js` 按平台改造（Vercel 放 `api/asr.js` 并 `export default`；自建 Node 起一个转发接口即可）。
3. 改前端：打开 `index.html`，把 `const BAIDU_ASR_PROXY = '';` 填为代理地址，例如 Netlify 下填 `'/.netlify/functions/asr'`，自建填 `'https://你的域名/asr'`。保存、重新上传覆盖即可。

**效果与边界**

- 配置后：中文方向（中→越）优先走百度 ASR，国内 Chrome/安卓直接说中文出字；越南语方向、iOS、未配置时自动回退浏览器内置语音识别。
- 代理报错（如密钥未配）时，前端会提示并自动降级，不会崩溃。
- 不配置 `BAIDU_ASR_PROXY`：语音输入行为与之前一致（走内置识别 + 输入法语音键）。

## 十一、V1.5.1 优化：越南语语音识别更准

越南语此前只走浏览器内置 `vi-VN` 识别、`maxAlternatives=1`（只取 1 个候选，遇同音词必错），且没有利用应用自带的789 条正确越南语词库。本版针对性优化：

### 1. 词库纠错引擎（默认可用，无需任何密钥）

- 应用自带 789 条正确越南语（场景 SC_A~D、SENT4 四类百句共 400 条、词库 VOCAB、金额 MONEY）被建成「标准答案库」。
- 每次识别拿到结果（含最多 5 个候选）后，自动与词库做**归一化相似度比对**（去声调、去标点、忽略大小写，再用编辑距离/包含关系打分），挑最贴近的一条填进输入框；若与原文不同，会短暂提示「已按词库校正：…」。
- 这一层对**工厂/产线行业词汇**误识效果最明显（识别器把近音词认错时，词库能拉回正确写法），且零成本、离线也能用。

### 2. 多候选优选

- 浏览器识别 `maxAlternatives` 由 1 提到 5，纠错引擎从 5 个候选里挑词库最贴近的——识别器常把正确句放在第 2、3 个候选，过去被直接丢弃。

### 3. 可选云端高精度：OpenAI Whisper（越南语/中文都支持）

- 百度 ASR 只支持中文，越南语想再上一个台阶就靠 Whisper。新增 `WHISPER_PROXY` 开关 + 服务端代理 `netlify/functions/whisper.js`：配置后在非 iOS 上**优先走 Whisper**（越南语、中文都走），准确度远超浏览器内置。
- 默认**关闭**（不配置则完全沿用上面的词库纠错 + 浏览器内置方案），不影响任何现有行为。
- 配置三步：
  1. 申请 OpenAI API Key：https://platform.openai.com/api-keys ；可选 `WHISPER_MODEL`（默认 `whisper-1`，可填 `gpt-4o-transcribe` 等）。
  2. 部署 `netlify/functions/whisper.js`（方式同第九节），并在托管后台设环境变量 `OPENAI_APIKEY`（可选 `WHISPER_MODEL`）。
  3. 前端 `index.html` 把 `const WHISPER_PROXY = '';` 填为代理地址，例如 `'/.netlify/functions/whisper'`。保存、重新上传即可。

> 决策顺序（非 iOS）：已配 Whisper → Whisper；中文且配百度 → 百度；否则 → 浏览器内置识别（越南语叠加词库纠错）。iOS 一律走浏览器内置（叠加词库纠错）。

### V1.5.1 改了什么

- 新增越南语词库纠错引擎（`normVi` / `simVi` / `bestViMatch` / `pickBestVi` + `VI_INDEX`），识别结果自动校正；
- 浏览器识别 `maxAlternatives` 1 → 5，越南语落权到词库最贴近候选；`recog.lang` 补充 `en-US`；
- 新增可选 Whisper 云端识别路径（`WHISPER_PROXY` 常量、`whisperASRAvailable` / `whisperASRDictate` / `transcribeWhisper` + `netlify/functions/whisper.js`）；
- 麦克风引导弹窗补充「词库纠错」「可选 Whisper」说明；
- 版本号 V1.5.0 → V1.5.1（`index.html` 内 `APP_VER`、`sw.js` 缓存名同步）。

## 十二、V1.6.0 新增：泰语 + 双语言选择器 + 客套语固定译法

### 1. 四语种、12 方向

互译页由原来 4 个固定方向胶囊，改为「**源语言 + 目标语言**」双下拉选择器（中间 ⇄ 一键交换），可选中文 / 越南语 / 英语 / 泰语，共 12 种方向。这是主流翻译工具（Google 翻译、DeepL、微软翻译）的通用做法，也为以后再加语种留出空间。

- 百度翻译语种码：`zh` / `vie` / `en` / `th`（依据：百度翻译开放平台《通用文本翻译API-接入文档》常见语种列表）；
- MyMemory 语种码：`zh-CN` / `vi` / `en-US` / `th-TH`（2026-11-06 实测 `zh-CN|th-TH` 可用）；
- 语音朗读/识别码：`zh-CN` / `vi-VN` / `en-US` / `th-TH`（`th-TH` 见 WICG Web Speech API 端侧识别语言列表）；
- `netlify/functions/translate.js` 透传 `from/to`，无需改逻辑即可支持泰语。

> 对话模式不再固定中⇄越，会自动跟随当前方向中的外语（中→泰时上半屏显示倒置泰文大字）。

### 2. 泰文排版单独处理（有依据，不是凭感觉设的）

泰文**无词间空格**，元音与声调符号最多上下四层堆叠。据 ThaiGraph《The Complete Guide to Thai Typography》与 Wikipedia「Thai typography」：

- 行高需 **1.55–1.8**（本版 `.thtxt` 取 1.75），沿用拉丁文 1.4 会让声调符撞上一行；
- 字号比拉丁文 **+5–10%**（本版取 1.08em）；
- **禁止 letter-spacing**（会拆散元音与辅音，变成乱码）；
- 字体栈优先 `Noto Sans Thai` / `Sarabun` / `Leelawadee UI`；元素带 `lang="th"`。

自检时请务必用真机看一眼泰文：重点看声调符有没有和上一行重叠、换行有没有把词截断。

### 3. 数据补齐泰语机翻初稿

789 条数据再加一列泰语：场景 SC_A~D 与 SENT4 四类百句（工厂/商务/生活/应急共 400 条）为**第 5 列**、金额 MONEY 为**第 6 列**、词库 VOCAB 为**第 5 列**。卡片新增 `TH:` 文字与「泰」朗读按钮，词库卡片同理，收藏结构同步扩展为 6 元素。

⚠️ **泰语为 MyMemory 机翻初稿，必须人工校对后再用于现场**。2026-11-06 对 20 条产线常用语抽样：14 条准确、4 条生硬可懂、2 条明显偏离（「今天加班」被译成"今天的加班费"、「可以了吗」被译成"那我们开始吧"）。另外泰语有男用 `ครับ` / 女用 `ค่ะ` 礼貌语尾之别，机翻会混用，安全 / 品质 / 金额类用语请务必找泰方人员确认。改法：直接编辑 `index.html` 对应条目的泰语列。

### 3.0 数字词 22 条的特殊处理（有依据，非机翻）

VOCAB 里有 22 条越南语数字词（0–1000），其中文意思是纯数字、英文列也多为数字。三个方向的 MyMemory 机翻对**短数字词都不可靠**（2026-11-06 实测：中→泰「三」返回 `3.2`、越→泰 `không` 返回「ไม่ใช่(不是)」、英→泰 `Two` 返回 `2`）。因此这 22 条不采用机翻，改按泰语通行数词写法核定，取值依据为**同批实测结果或其词根**：

- `0 ศูนย์`←Zero、`1 หนึ่ง`←One、`2 สอง`←hai、`7 เจ็ด`←Seven、`9 เก้า`←Nine、`10 สิบ`←Ten、`11 สิบเอ็ด`←Eleven、`20 ยี่สิบ`←Twenty / 二十（多方向实测一致）；
- `30 สามสิบ`、`40 สี่สิบ`、`50 ห้าสิบ`、`60 หกสิบ`、`70 เจ็ดสิบ`、`80 แปดสิบ`、`90 เก้าสิบ`、`100 หนึ่งร้อย`、`1000 หนึ่งพัน` 由英/越/中→泰实测直接得到（已剥除机翻附带的罗马音）；
- `3 สาม` / `4 สี่` / `5 ห้า` / `6 หก` / `8 แปด` 由上述实测复合数词（สามสิบ / สี่สิบ / ห้าสิบ / หกสิบ / แปดสิบ）拆出词根，**非凭空填写**。

仍建议泰方人员复核这 22 条（尤其 `11 สิบเอ็ด`、`20 ยี่สิบ` 是泰语特殊读法）。改法同其他条目：直接编辑 `index.html` 对应泰语列。

### 3.1 跨外语方向的实测风险（重要）

12 方向里有 6 个是「外语 → 外语」（如 越→泰、泰→英），这些方向没有应用场景库固定语句可兜底，全部依赖机翻。2026-11-06 对 MyMemory 做了 8 条抽样：

| 方向 | 结果 |
| --- | --- |
| 越→泰 / 英→泰 / 泰→英 / 越→英 / 泰→中（开始生产） | 7 条可用 |
| 泰→中（你好 `สวัสดีครับ`） | 返回完全无关的「(本的声音) 亲爱的激情面包师…」——MyMemory 记忆库脏数据 |
| 中→泰（不客气） | 漏译，直接返回英文 `You're welcome.` |

对应处理：

- **译文语种校验**：目标是中文/泰文却不含对应字符时，判为漏译并明确报错，不把英文塞给用户；
- **界面提示**：源与目标都不是中文时，方向说明栏会显示「跨外语方向为机翻初稿，请人工确认」；
- 记忆库脏数据（返回了另一句不相干的外语）**程序无法自动识别**，只能靠现场人工留意。要稳就按第六节配百度翻译代理（跨语种质量更可控），或让对方用中文做中转。

### 3.2 机翻漏译条目的重查（10 条）

全量生成后按「泰语列是否含泰文字符」逐条抽检，发现 **10 条被 MyMemory 记忆库固定错映射成英文**，其中还夹有脏数据（「几点了？」→ `What time is it? Fuck!`、「不合格」→ `Please check the latest Gattaca bulletin.`）。重复查同一句无法绕开，改用**中文同义改写 + 规范英文转译**重新实测，取返回泰文的合理结果：

| 中文源 | 修正后泰语 | 依据 |
| --- | --- | --- |
| 不客气 | `ไม่เป็นไร` | 「不用谢」中→泰实测 |
| 不合格 | `ไม่เป็นไปตามข้อกำหนด` | 「不达标」中→泰实测 |
| 检查一下 | `โปรดตรวจสอบ` | 「请检查」中→泰实测 |
| 错 | `ผิดพลาด` | 「错误」中→泰实测 |
| 几点了？ | `กี่โมงแล้วเนี่ย?` | 「几点了？。」中→泰实测 |
| 交接班 | `การเปลี่ยนกะ` | `Shift change` 英→泰实测 |
| 再见 | `ลาก่อน` | `Goodbye` 英→泰实测 |

修正后 789 条泰语列**全部含泰文字符**。另对抽检发现的 3 条语义错译做了定向重查：「在这里签字」→`กรุณาลงชื่อตรงนี้`（「请在这里签名」实测）、「我住XX酒店」→`ฉันพักที่โรงแรม XX`（`I stay at XX hotel` 实测）、「不行」→`ไม่ได้`（四条机翻路径全部错译，取同批实测 `ฉันไปไม่ได้`「去不了」中的标准否定词根）。仍需按第 3 节的提醒做人工校对。

### 4. 高频客套语固定译法层（PHRASE_FIX）

机翻对中文客套语系统性出错：实测「初次见面请多多关照」在中→越、中→英、中→泰三语里全部被误译为「第一次见面要小心 / 保重」，「不客气」的泰语甚至漏译、直接返回英文。现新增 `PHRASE_FIX` 表，命中即返回固定译法、不走机翻，四语共用。

表中译法来自同批实测里的正确片段与应用场景库已有固定语句（详见 `index.html` 内 `PHRASE_FIX` 上方注释），**不是凭空编写，但仍属待人工校对初稿**，确认后直接改表即可。

### 5. 顺带修正两处遗留缺陷

- **金额卡片参数错位**：V1.5.0 起金额卡把英文列当成了语言码、谐音显示成 `vi`，本版修正为正确的参数顺序。
- **词库纠错误替换**：V1.5.1 的越南语纠错无条件采用词库最贴近条目，识别结果与词库完全无关时也会被改成别的句子；本版加 **0.75 相似度阈值**，低于阈值保留识别原文。泰语识别也接入同一套纠错框架（另写 `normTh` / `pickBestTh`，泰文不套用越南语去声调逻辑）。

- 版本号 V1.5.1 → V1.6.0（`APP_VER`、`APP_DATE`、页面标题、`sw.js` 缓存名 `huayue-v1.6.0` 同步）。

## 十三、V1.7.0 新增：对话模式双模 + 说话方配色 + 机翻来源标记

### 1. 为什么要做双模，而不是直接换成聊天气泡

V1.6.0 及以前的对话模式是**上下分屏**：上半屏 `rotate(180deg)` 倒置大字给对面的人看，下半屏给自己看，服务的是「手机平放推过桌面」的现场——产线戴手套、噪音大、两人不必抢手机。主流翻译 App 的**聊天气泡流**服务的是另一种现场：手机竖握、两人轮流按同一个麦克风。两种场景都真实存在且不互斥，所以本版做成**可切换**，不替换：

- 顶部 chips「气泡流 / 对面屏」，默认气泡流，选择写入 `localStorage` 的 `hy_conv_mode`，下次打开仍记得；
- 两种模式**共用同一份会话数组**（最多 30 条），切过去不丢记录；
- 「对面屏」保留原有的倒置大字、朗读、慢速朗读，行为与 V1.6.0 一致。

### 2. 说话方颜色为什么要另定，不能照抄竞品

竞品用粉红 `#ffe2e0`（我方）/ 浅蓝 `#e1ebff`（对方）区分说话方。但本应用从 V1.5.0 起已用颜色表示**语种**：越南语 `#1f5b4a` 绿、英语 `#2f6fb0` 蓝、泰语 `#7a4b9e` 紫。若把浅蓝用作「对方」，英语方向就会出现「蓝色既代表英语、又代表对方」的语义冲突。

本版的处理：

| 维度 | 取值 | 位置 |
| --- | --- | --- |
| 说话方 | `--me` 浅棕 `#f5e7e0` / `--them` 灰绿 `#e9efec`（暗色 `#3a2a24` / `#24302a`） | 气泡底色 |
| 语种 | `--vi` / `--en` / `--th`（中文用 `--brand`） | 气泡边 3px 竖条，不参与底色 |
| 辅助编码 | 左右对齐 +「我 · 中文」/「对方 · 越南语」文字标签 + 气泡下角直角 | 不只靠颜色 |

辅助编码不是多余：按 WCAG 相对亮度公式算，竞品那两个浅色对白底都只有约 **1.2:1**，低于 WCAG 2.1 SC 1.4.11 对非文本视觉信息的 3:1 要求，车间强光或色弱时更难分。

### 3. 每条气泡的来源标记（不冒充准确）

气泡底部固定显示译文来源，四级区分，避免把机翻初稿当准话用：

| 标记 | 含义 |
| --- | --- |
| `固定译法（人工核过）` | 命中 `PHRASE_FIX` 客套语层（如「初次见面请多多关照」） |
| `场景库固定语句` | 命中场景库 / 百句库的**越南语列**（原版人工语料，非机翻） |
| `场景库词条（机翻初稿）` | 命中同一词库的**英文列 / 泰语列**（V1.5.0 / V1.6.0 机翻初稿，不冒充固定译法） |
| `机翻初稿 · 关键用语请确认` | 走 MyMemory / 百度机翻 |

优先级：`PHRASE_FIX` → 场景库词条 → 机翻。命中前两级不联网。

### 4. 语音与方向

- 底部大红圆形按钮为**单键麦克风**，复用 `startDictation`；说完后自动翻译，不需要再点「翻译并显示」。
- 「我 / 对方」chip 决定**语音识别语种**：Web Speech 必须显式指定 `lang`，无法自动判语种，这一步技术上省不掉；保持常驻，切一次即可连续说多句。
- **翻译方向改为按输入是否含中文自动判定**（`detectLang(src) === 'zh'`），去掉旧的「换方向」手点。顺带修掉一个 V1.6.0 遗留缺陷：`detectLang('Hello')` 返回 `latin` 而不是 `en`，旧逻辑用 `detectLang(src) === cvF` 判方向，导致**对方说英语时会被当成中文翻成英文**。
- 打字输入仍保留「翻译并显示」按钮；回车等同点击。

### 5. 本版明确不动的部分

- 789 条数据列、12 方向翻译逻辑、`translate.js` / `asr.js` / `whisper.js`、所有历史备份一律未改，因此**本版不会引入新的机翻错误**。
- 气泡流不自动导入「历史」页记录：历史项不带说话方与来源信息，导入会把别的语种译文混进当前对话并误标来源。

### 6. 顺带修掉的三处 V1.6.0 遗留交互缺陷

| 缺陷 | 表现 | 本版处理 |
| --- | --- | --- |
| 语音指引销毁会话 | 在对话模式里点麦克风，若浏览器不支持语音识别，`showMicGuide` 会整段改写 `#mask.innerHTML`，已说过的话全部消失、对话被强制关闭 | 对话模式内改为 `.cv-guide` 内嵌浮层，点「知道了」只关浮层，会话数组与屏幕内容都保留 |

| 对面屏语种色写死 | 上半屏倒置大字 CSS 固定 `color:var(--vi)`，切到泰语/英语方向仍显示越南语绿 | 按当前目标语种注入 `var(--th)` / `var(--en)` / `var(--vi)` |

### 7. 自检与已知风险

- 新增三条自检项见第四节（双模记忆、说话方分色、来源标记）。
- **泰文气泡**复用 `.thtxt`（行高 1.75、字号 19px、禁 letter-spacing、`lang="th"`），真机上仍需确认声调符不撞行。

- 版本与文件：`APP_VER=1.7.0`、`APP_DATE=2026-11-06`、页面标题、`sw.js` 缓存名 `huayue-v1.7.0` 同步；改动文件仅 `index.html`、`sw.js`、本文档。

## 十四、V1.7.1：iPhone 顶部安全区 + 底部状态提示避让

### 1. 问题（用户真机截图，2026-11-06）

对话模式顶部「关闭」「气泡流 / 对面屏」与状态栏时间 `21:29`、右上角状态图标重叠；底部状态提示「已加入对话。机翻初稿，关键用语请确…」被 Netlify Drop 注入的「Powered by Netlify」浮标盖住右半截。

### 2. 根因

| 位置 | 现状 | 判断 |
| --- | --- | --- |
| `index.html` 第 6 行 | `<meta ... viewport-fit=cover>` | PWA 全屏必须开，页面会延伸到刘海/状态栏之下，**正确**，问题不在这里 |
| `#mask.convmode{padding:0}` + `.conv-head{padding:8px 12px}` | 顶部完全没有 `env(safe-area-inset-top)` 补偿 | **根因**：整屏 0 padding，顶栏自己只留 8px |
| `.conv-in` / `.tabbar` | 都写了 `env(safe-area-inset-bottom)` | 底部做了、顶部漏了，属于单边遗漏 |
| `.conv-tip` 原在 `.conv-in` 最末尾 | 垂直位置落在右下角浮标区域 | 次要问题 |

### 3. 改动（只有 CSS + 一处模板顺序，数据与翻译逻辑一律未动）

- `.conv-head` 上内边距 → `calc(8px + env(safe-area-inset-top, 0px))`。**由系统给值，不写死像素**：刘海 / 灵动岛机型顶栏自动下移让开状态栏；安卓和普通浏览器该值为 `0`，与改前一致，不会多出空白。`.conv-body` 是 `flex:1`，自动缩短，不会撑出滚动条。`.mini` 按钮本来就有 `min-height:42px`，触控区够，未改。
- 把 `<div class="conv-tip" id="cvTip">` 从输入区最末尾移到 `.cv-who` 之后、输入框之前；`.conv-tip` 外边距由 `margin-top:8px` 改成 `margin:0 0 8px` 并加 `min-height:18px` 减少文字变化时的跳动。提示是操作反馈，贴近输入区更顺，也彻底离开右下角。
- `.cv-micwrap` 下内边距 `2px → 28px`，补回提示行移走后少掉的约 26px 高度：输入区总高不变、**圆形麦克风按钮的垂直位置不变**，不会因为少了一行文字而下沉到浮标区域；腾出的底部留白正好让给徽标与 Home 指示条。

## 十七、V1.7.5：Netlify 推广徽标遮挡底部导航（最终解法）

**现象**：部署到 Netlify 后，右下角「Powered by Netlify」深色胶囊压住底部导航的「互译 / 速查 / 收藏」。

**来源**：徽标不在本包里（`index.html` 全文没有它），由 Netlify 边缘服务器在返回页面时注入，渲染在隔离节点 / iframe 中，页面 CSS `display:none` 无效，脚本也可能读不到它。

> **V1.7.4 的教训**：上一版试图用 `document.querySelector('[id*="netlify"]')` 检测徽标再留白，但徽标在隔离节点里，检测**没有命中**，所以留白从未触发，用户反馈「还是遮挡」。V1.7.5 起改为**不依赖检测**的物理避让。

**本版做法**：

```css
:root{ --nbres:46px }              /* 默认预留底部安全带 */
#app{ height:100dvh; padding-bottom:var(--nbres,0px) }
```

整个 `#app` 上移 46px，徽标固定落在这段留白里，六个导航按钮始终在其上方，互不重叠。留白使用页面背景色，视觉上等同于底部安全区，不突兀。

只在**确认没有徽标**的环境里取消留白（白名单，不依赖 DOM 检测）：

```js
if (/workbuddy\.host$/i.test(location.hostname) ||
    location.hostname === 'localhost' ||
    location.hostname === '127.0.0.1') {
  document.documentElement.style.setProperty('--nbres', '0px');
}
```

- Netlify（含自定义域名）：46px 留白生效，按钮不再被盖；
- 演示链接 `workbuddy.host`、本地预览：0px，底部干净无多余空白；
- Cloudflare Pages / GitHub Pages 等无徽标托管：会多出 46px 留白，不影响功能。若要去掉，把上面白名单加上你的域名，或把 `--nbres` 改为 `0px`。

**治本（推荐，仍建议做一次）**：Netlify 后台 → 项目 → **Project configuration / Site settings** → **General** → 关掉 **Powered by Netlify badge** → 保存，下一次请求即生效，不用重新部署。关掉后徽标消失，留白仍在，可按上一条把 `--nbres` 设为 0。

### 1. 乱码的根因（不是 OCR 玄学，是语种选错）

### 2. 识别链路改了什么
- **两个语种下拉合并成一个 chip 组**（中文 / English / Tiếng Việt / ไทย / 中英混排），

## 二十、V1.7.8：拍照翻译接腾讯云 OCR（精度）+ 拍完自动识别翻译（流程）

来源：2026-11-16 用户反馈「拍照翻译功能精度太差了，无法自动识别翻译，参考同类软件优化一下」。
基线 V1.7.7（已修语种选错乱码 + 预处理 + 置信度告警），本版解决「精度上限」与「要手动两步」两个问题。
**只改拍照翻译这一块 + sw.js 白名单**，其余 6 个 tab、789 条语料、翻译链路、对话模式、汇率、Netlify 其它函数全部未动。

### 1. 为什么必须上云 OCR（不吹）
V1.7.7 用 Tesseract.js 纯前端，对**屏幕翻拍（摩尔纹）、手写、反光、小字**识别率远低于
微信扫一扫 / Google Lens 这类云端 OCR，这是引擎天花板，参数调不出质变（上次已说明）。
同类软件的识别能力来自自家云模型。本项目四语种（中/越/英/泰）覆盖最全且国内可注册的是
**腾讯云通用印刷体识别（GeneralBasicOCR）**：官方确认支持 21 语种，**含越南语 vie、泰语 tha**，
各语种可与英文混合，`LanguageType` 可显式指定；准确率标准版 96% / 高精度版 99%。
**免费额度：首次开通后每月 1000 次**（共享资源包，每月 1 号发放、当月有效），
后付费 0.15 元/次起步，原型期基本零成本。Netlify Functions 跑在海外，调 `ocr.tencentcloudapi.com` 无墙。

### 2. 改了什么
- **新增 `netlify/functions/ocr.js`**：腾讯云 API 3.0 TC3-HMAC-SHA256 签名（Node 内置 crypto，无新依赖），
  读环境变量 `TENCENT_OCR_SECRET_ID` / `TENCENT_OCR_SECRET_KEY`；入参 `{imageBase64, langKey}`，
  语种映射 `zh→zh`、`en→mix`、`vi→vie`、`th→tha`、`mix→mix`；返回
  `{engine:'tencent', text, confidence(取各行最小), language, angle, count}`。
  **未配置密钥返回 `{engine:'none'}`，配置但调用失败返回 502 `{engine:'error'}`**——都不抛 5xx，前端据此分流。
  密钥只在服务器端，不出浏览器；图片 base64 上限 7MB（前端已压到长边 2200 / JPEG 0.82）。
- **前端识别优先云端**：`ptCloudOCR()` 调 `/.netlify/functions/ocr`；成功用云端文本+置信度，
  未配置（engine:none）或失败自动回退本地 Tesseract（V1.7.7 的 worker/预处理逻辑原样保留）。
  状态行明确标注「引擎 腾讯云OCR / 引擎 本地识别」，置信度与语种不符告警沿用 V1.7.7。
- **拍完自动识别 + 自动翻译**（对齐同类软件）：新增「自动识别翻译：开/关」按钮，默认开——
  选图即自动识别，识别完自动翻成其余三语种；关掉则保留手动两步。「开始识别 / 翻译成其余三语种」按钮仍在。
- **开关选择持久化**：`自动识别翻译` 状态存 `localStorage`（键 `vn_ptAuto`），关掉再进拍照翻译仍是「关」，
  不会出现按钮显示「开」却实际为「关」的错位。
- **引擎标注常显**：识别完成后在状态行下方固定显示「识别引擎：腾讯云OCR/本地识别 · 可信度 X%」，
  不会被「正在翻译…」覆盖，用户能确认这次到底用了哪个引擎。
- **sw.js**：缓存名 `huayue-v1.7.8`，放行 `/.netlify/functions/ocr`（同源走网络、不进缓存）。
- 版本：`APP_VER=1.7.8`、页面标题、`verTag`；`APP_DATE` 保持 2026-11-11。

### 3. 使用方式（三步启用云端，不改代码）
1. 腾讯云注册并**实名认证** → 访问管理 CAM → API 密钥管理 → 新建密钥，拿到 `SecretId` / `SecretKey`；
   在「文字识别」控制台开通通用印刷体识别（开通即享每月 1000 次免费）。
2. Netlify 站点 → Site settings → Environment variables → 添加 `TENCENT_OCR_SECRET_ID`、`TENCENT_OCR_SECRET_KEY`。
3. 重新部署（或触发一次 Build & Deploy）。之后 App 里拍照翻译自动走云端，状态行出现「引擎 腾讯云OCR」。
